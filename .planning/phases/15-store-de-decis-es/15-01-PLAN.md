## Phase Goal

O backend sabe registar uma decisão sobre uma vaccine num registo de auditoria só de acréscimo, e deriva o estado atual sem nunca alterar a vaccine.

(Goal do ROADMAP citado tal como está; MVP_MODE está desligado, por isso não há user story.)

<objective>
Pôr de pé, ponta a ponta, a fatia "um analista aprova (ou rejeita com motivo) uma vaccine e a leitura mostra o estado derivado": regra pura (`scripts/vaccine_decision.py`) -> tabela `vaccine_decisions` no mesmo `vaccines.sqlite3` -> `VaccineStore.decide_vaccine` numa transação `BEGIN IMMEDIATE` -> `get_vaccine`/`list_vaccines` com `state` derivado e bloco `decision`. Depois, endurecer a entrada: todos os códigos de validação, por ordem fixa, antes de tocar no disco.

Purpose: o esquema de `vaccine_decisions` é a porta sem volta desta fase (D-01 e D-03, `one-way`): fica gravado nos `vaccines.sqlite3` existentes à primeira escrita. A Task 1 confirma o DDL exato com o utilizador antes de o gravar; o tracer prova o caminho inteiro sobre esse DDL antes de os planos 15-02 e 15-03 acrescentarem as recusas, a corrida e as provas ao nível do ficheiro.

Output: `scripts/vaccine_decision.py`, `scripts/test_vaccine_decision.py`, `scripts/test_vaccine_decision_store.py` (novos); `scripts/vaccine_store.py` e `scripts/test_vaccines_api.py` (alterados).

Decisões implementadas: D-01, D-02, D-03 (DDL; as provas por SQL direto são o plano 15-03), D-04, D-05, D-06 (forma da transação; a prova de corrida é o plano 15-02), D-07, D-08, D-10 (leitura sem tabela; a prova de bytes inalterados é o plano 15-03), D-11, D-12, D-13, D-14. - **Motivo (D-12):** uma linha de texto simples: depois do `strip`, recusa qualquer caracter de categoria Unicode `Cc`, `Cf`, `Cs`, `Co`, `Cn`, `Zl` ou `Zp` (inclui quebras de linha, tabulação, zero-width e overrides bidi). - **Chave estrangeira (D-07):** `vaccine_id ... REFERENCES vaccines(id)`, com `PRAGMA foreign_keys = ON` só na ligação de decisão; a existência é sempre verificada explicitamente na transação.

## DDL a fixar (contrato que a Task 1 confirma; entra em `DECISIONS_SCHEMA` tal e qual)

```sql
CREATE TABLE IF NOT EXISTS vaccine_decisions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    vaccine_id TEXT NOT NULL UNIQUE REFERENCES vaccines(id) CHECK (vaccine_id GLOB 'vac-*' AND length(vaccine_id) = 16),
    decision TEXT NOT NULL CHECK (decision IN ('approved', 'rejected')),
    decided_by TEXT NOT NULL CHECK (decided_by GLOB 'analyst-?*' AND decided_by NOT GLOB '*[^a-z0-9-]*' AND length(decided_by) <= 72),
    decided_by_name TEXT NOT NULL CHECK (length(decided_by_name) BETWEEN 1 AND 128),
    decided_at TEXT NOT NULL,
    reason TEXT CHECK (reason IS NULL OR (length(reason) BETWEEN 1 AND 500 AND length(trim(reason, char(32, 9, 10, 13))) > 0)),
    previous_state TEXT NOT NULL CHECK (previous_state = 'proposed'),
    CHECK (decision <> 'rejected' OR reason IS NOT NULL)
);
CREATE TRIGGER IF NOT EXISTS vaccine_decisions_no_update BEFORE UPDATE ON vaccine_decisions
BEGIN SELECT RAISE(ABORT, 'vaccine_decisions e append-only'); END;
CREATE TRIGGER IF NOT EXISTS vaccine_decisions_no_delete BEFORE DELETE ON vaccine_decisions
BEGIN SELECT RAISE(ABORT, 'vaccine_decisions e append-only'); END;
```

Colunas e CHECK de `decision`/`previous_state`/`UNIQUE` são D-02 à letra; o CHECK do motivo e o CHECK de tabela são D-12; os triggers são D-03; `REFERENCES` é D-07; os CHECK de `vaccine_id`, `decided_by` e `decided_by_name` são defesa em profundidade à discrição do planner (espelham `vaccines.id`, `AnalystCreate.id` e `AnalystCreate.name`). `decided_at` fica só `NOT NULL`, como D-02 diz; o formato UTC é validado no código.
